## 先说这版已经解决好的东西

我认为下面这些可以冻结，不用继续摇摆：

- `AgentSessionKey = GameID + WorldID + EntityID`，Identity Contract 没问题。
- `WorldID` 不再从 `AdapterHello` 获取，而是随 `GameEvent / ObserveRequest / Observation / ActionRequest` 传递，这比之前清晰很多。
- `EnvironmentSession = Game/Adapter live connection`，允许同一连接经历标题页 → Save A → 标题页 → Save B。
- `ActionRequest.world_id` + Adapter `world_mismatch` 防护非常值得加，它把“旧 Turn 穿越到新存档执行动作”的风险用很低成本挡住了。
- `target_entity_id` 是 typed field，并要求引用 `event.entities`，路由 contract 已经清楚。
- `EventAck → admitted barrier → AgentTurn → ObserveRequest` 的顺序现在正确。
- `ExecutionLane = queue + worker`，同 Agent 串行、不同 Agent 并行，继续保持这个方案即可。
- Protocol 正式升 `v1alpha2` 是合理的，现在修改成本最低。

# P0-1：`Observe world_mismatch` 的“返回路径”还没真正定义完整

这是我认为目前最重要的剩余问题。

你现在写的是：

```text
HandleObserveOnMainThread
    request.WorldId != currentWorldId
    → Error(code=world_mismatch)
```

Protocol 本身能表达，因为 `AdapterMessage` 已经支持通用 `Error`，并且请求/响应可以通过 `correlation_id` 关联。

但当前 Phase1 实现事实又明确写过：

> Observe 失败目前没有独立失败响应通道。

也就是说，现在正常路径大概是：

```text
ObserveRequest
    ↓
pendingObservations[message_id]
    ↓
等 Observation
```

而 Phase3 新增：

```text
ObserveRequest
    ↓
Error(world_mismatch)
```

那么 Gateway 必须明确知道：

> 这个 `Error` 是哪个 Observe waiter 的失败结果。

### 建议直接把 contract 补成

```text
ObserveRequest:
    message_id = msg_100

Adapter 检测 world mismatch:

AdapterMessage:
    correlation_id = msg_100
    error.code = world_mismatch
```

Runtime `recvLoop`：

```text
收到 Error
↓
correlation_id 命中 pendingObservation
↓
resolve waiter with error(world_mismatch)
↓
删除 pending waiter
↓
Environment.Observe 返回 error
↓
AgentTurn:
    turn_failed
    stage=observe
    reason=world_mismatch
```

也就是说，§7.2 `stream_environment.go` 再补一句：

```text
recvLoop 必须允许 correlated Error 解除 pending Observe，
而不只允许 Observation 解除 pending Observe。
```

并补两个测试：

```text
ObserveRequest → correlated Error(world_mismatch)
→ Observe 立即返回错误，不等待 timeout

correlated Error 处理后迟到 Observation
→ 忽略，不再次 resolve waiter
```

## 另外成功的 Observation 也应该反向校验 scope

既然你已经让：

```text
Observation {
    entity_id
    world_id
}
```

都返回了，那 Runtime 就应该真的利用它。

比如 Runtime 请求：

```text
world_id  = Save_A
entity_id = npc:Abigail
```

Adapter 却因为 bug 返回：

```text
world_id  = Save_B
entity_id = npc:Abigail
```

不能因为 `correlation_id` 正确就接受。

建议：

```text
Observation.WorldId != requested WorldID
OR
Observation.EntityId != requested EntityID

→ Observe failed
→ reason=observation_scope_mismatch
```

这样完整链路变成：

```text
AgentSessionKey
       ↓
ObserveRequest(world/entity)
       ↓
Adapter
       ↓
Observation(world/entity)
       ↓
Runtime 再验证一次
```

这是 Identity/World contract 很重要的一道闭环。

# P0-2：既然重新定义了 ACCEPTED，必须顺便定义 DUPLICATE / event delivery

你现在已经非常明确地把：

```text
ACCEPTED
```

从 v1alpha1 的：

> durable / reliable acceptance

改成：

> 当前 EnvironmentSession 内的 runtime admission。

这个修改我赞成。

但旧 v1alpha1 不只是定义了 `ACCEPTED`，它还定义了：

```text
At-Least-Once Event Delivery

ACCEPTED
DUPLICATE
REJECTED

event_id 去重
Adapter pending queue
```



现在 Phase3 只重新定义了 ACCEPTED，却没回答：

> **v1alpha2 里的 `DUPLICATE` 还存在吗？Adapter 还会 retry 吗？Runtime 还要根据 event_id 去重吗？**

这个要一起收。

### 我推荐一个非常轻的方案

不用磁盘，不影响游戏延迟：

```text
v1alpha2 Phase3 Event Delivery

Runtime 在当前 EnvironmentSession 内维护：
    seenEventIDs map[string]struct{}

第一次 event_id：
    admission 成功
    → 记录 seenEventID
    → ACCEPTED

同一 EnvironmentSession 再收到同 event_id：
    → DUPLICATE
    → 不重新创建 Turn

Runtime disconnect / crash：
    → seenEventIDs 丢失

Phase3 不保证：
    跨 reconnect 去重
    跨 Runtime restart 去重
    durable replay
```

这个就是一个 Go map，基本没有性能问题。

于是你仍然能保留：

```text
ACCEPTED
DUPLICATE
REJECTED
```

但是正式降低保证：

```text
v1alpha1:
    durable idempotency

v1alpha2 Phase3:
    in-EnvironmentSession idempotency
```

Phase7 再升级成 durable。

### 同时把 sequence scope 写清楚

现在 EnvironmentSession 能跨 Save：

```text
Save_A
↓
Save_B
```

那么建议规定：

```text
GameEvent.sequence
=
EnvironmentSession scoped monotonic sequence

切换 World 不重置。
```

例如：

```text
Save_A event: 101
Save_A event: 102
切 Save_B
Save_B event: 103
```

而不是回到 1。

否则旧 Protocol 中：

```text
Heartbeat.last_event_sequence
```

这类 connection-level 信息会产生歧义。

# P1-1：admission barrier 和 Close/Drain 还有一处文字上的状态缺口

你现在 barrier 已经设计正确：

```text
worker dequeue
↓
等待 task.admitted
↓
ACK 成功
↓
close(admitted)
↓
Turn
```



但是 §6.4 又写：

> 已被 worker 取出的 event 由 worker 负责进入 AgentTurn 或按 active turn 失败路径收敛。

这里不完全准确。

因为存在：

```text
worker 已经 dequeue
但还卡在 admitted
```

此时它**还不是 active Turn**。

如果这里连接关闭：

```text
worker dequeue
↓
waiting admitted
↓
ctx.Done
```

正确结果应该还是：

```text
event_aborted_before_turn
```

而不是：

```text
turn_failed
```

所以建议正式冻结三个边界：

```text
1. task 还在 queue
   → Drain
   → event_aborted_before_turn

2. task 已 dequeue，但还没有 turn_started
   → worker 自己记录 event_aborted_before_turn

3. 已 emit turn_started
   → 之后发生任何连接失败
   → turn_failed
```

这样：

> **`turn_started` 是 Event lifecycle 和 Turn lifecycle 的唯一分界点。**

非常清楚。

# P1-2：Queue 默认 16，我还是建议降到 1

这不是 correctness 问题，是游戏体验问题。

现在配置：

```text
SessionQueueSize = 16
```

意味着一个 NPC 可以存在：

```text
1 个 active Turn
+
16 个 queued Turn
```

也就是最多 **17 次待处理玩家点击**。

假设一次 LLM 交互 3 秒：

```text
玩家狂点 Linus 10 次

第 10 次事件
可能 20～30 秒后才 Observe
```

这个 Event 到执行时上下文已经非常陈旧了，而且还会产生大量无意义 LLM 调用。

你的 Phase3 当前又明确不做：

```text
DROP
COALESCE
TriggerControl
```

所以最便宜的保护就是：

```text
SessionQueueSize default = 1
```

效果：

```text
Turn A active
Turn B queued
Turn C → session_queue_full
```

刚好又能满足 Phase3 的验收：

> 连点同一 NPC 两次，可以证明 FIFO 串行。

如果你想稍微宽松：

```text
default = 2
```

也可以。

**16 可以留给 stress test 配置，不建议作为游戏默认值。**

# P1-5：World 切换以后 Lane 数量描述要改一下

现在 EnvironmentSession 可以：

```text
Save_A
↓
Save_B
↓
Save_C
```

但 LaneStore 生命周期直到 stream disconnect。

所以如果：

```text
Save_A → 点过 10 NPC
Save_B → 点过 10 NPC
```

LaneStore 中实际上会留下：

```text
20 个 AgentSessionKey
```

不是“当前世界大约几十个 NPC”。

所以 §13.3：

> active lane 数约等于当前活跃 NPC 数

现在不再严格成立。

Phase3 不需要因此实现 idle eviction。

改成 Known Limitation 即可：

```text
LaneStore 在一个 EnvironmentSession 内不回收已创建 lane。
因此跨多个 WorldScope 切换后，lane 数量等于本连接历史上访问过的
AgentSessionKey 数量，而不是仅当前 world 的 NPC 数量。

Phase3 预期规模仍有界，不做 idle eviction。
```

就够了。
